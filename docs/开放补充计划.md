# 开放补充计划（待认领清单）

> **这不是使用手册。** 它是一张「缺口清单」：课程初始任务说明里要求的那些方面，我们只做完了一部分；
> 剩下的，欢迎后来的人接着补——包括你。
>
> 每项标注「要求什么 / 我们做到哪 / 还缺什么 / 交什么算完成」。状态是我们的自评，**欢迎推翻**；
> 推翻本身也是一次有价值的贡献。

## 0. 背景三句话

1. 阅有期是「借阅到期 → 宽限 → 申诉」的冲突设计作业的产品化实现：管理端（React）、Android 客户端（Flutter）、后端（Spring Boot + MySQL / Redis / RabbitMQ）。
2. 初始任务给的不是功能清单，而是一套**伦理设计框架**：三个冲突 A / B / C、三种平衡策略（分离 / 交换 / 补偿）、三方利益矩阵、伦理四问、阶段一 / 二交付物、8 分钟分享与互评。
3. 我们主攻 **冲突 A（个性化 vs 隐私权）**，B / C 只碰到边；四问里「透明可解释」答得最虚。下面逐项摊开。

## 1. 缺口总表

| 编号 | 要求 | 我们做到哪 | 还缺什么 | 交付物形态 |
|---|---|---|---|---|
| **G1** | 冲突 A：个性化 vs 隐私权 | 已覆盖：宽限依据 + 数据最小化 + 隐私开关 | 「用完即忘」缺**可验证证据**（数据存多久、怎么删） | 设计说明 + 可复现验证步骤 |
| **G2** | 冲突 B：自动化 vs 人性化 | 部分：有申诉通道与人工受理 | 人机分工边界没写死：哪些必须人审、误判多久纠正、兜底 SLA | 边界表 + 界面改造说明 |
| **G3** | 冲突 C：便捷 vs 公平 | 弱：有预约队列，缺续借公平性规则 | 热门书续借上限、动态限额、排队优先级与「看得见的预计归还时间」 | 规则设计 + 参数表（可选实现） |
| **G4** | 平衡策略：分离 / 交换 / 补偿 | 用了「分离」和「交换」 | 「补偿」几乎没有：让渡的利益没有从别处补回来 | 给 G3 写一个补偿方案（一页） |
| **G5** | 三方利益矩阵 | 只有冲突 A 一版 | 补 B / C 两版；补「被牺牲方如何被补偿」一列 | 表格（读者 / 图书馆 / 其他读者） |
| **G6** | 伦理四问（NFR-ETH-1..4） | 四问都有初答 | 每问缺「**可指认的界面元素**」与一个反例；第三问最弱 | 逐问走查表（是/否 + 依据 + 界面位置） |
| **G7** | 阶段一 / 二交付物 | 原型、方案书、提示词记录都有 | 迭代记录只留结论，缺「被推翻的版本与原因」 | 版本对照文档 |
| **G8** | 8 分钟分享 + 互评 | 有分享稿 | 缺对互评三问的自答准备；现场演示没有兜底方案 | 讲稿增补 + 90 秒录屏脚本 |
| **G9** | 评分项自查（30/25/20/15/10） | 没有对照表 | 按评分项逐条自评并给出证据链接 | 一页自查表 |

> G1–G9 是按「初始任务里的方面」切的，不是按代码模块切的。认领一项就够，不需要动整体架构。

## 2. 怎么认领

1. **先开 issue**：标题 `gap: G3 冲突C 续借公平性`，正文写「打算怎么答、需要哪些材料」，避免撞车。
2. **交付位置**：
   - 纯方案 / 表格 → `docs/gaps/G<n>-<短名>.md`
   - 涉及界面 → 同目录 + 脱敏截图
   - 涉及代码 → 提 PR，并在文档里互链
3. **完成的三个标准**（缺一不算完）：
   - 说清「要求什么 → 原来怎么答 → 你现在怎么答 → 为什么」；
   - 每个「是」都能指到一个**界面元素 / 代码位置 / 数据**；
   - 别人照着你的步骤能复现。
4. **评审口径**沿用课堂互评三问：真的化解冲突了吗？伦理立场在界面上找得到吗？如果我是被牺牲的那一方，我服气吗？

## 3. 补充时请守住三条边界

- **隐私**：不要提交真实姓名、学号、手机号、邮箱、服务器地址、密钥。截图打码沿用现有标准（`陈* / 2021***01`）。
- **伦理**：新方案必须过四问；「只照顾一方」的方案按课堂规则直接判负。
- **依赖**：不要引入付费服务、需要企业资质的东西，或必须联网才能演示的组件。

## 4. 已经踩过的坑（省你两天）

| 现象 | 真因 | 处理 |
|---|---|---|
| 登录返回 `403 Invalid CORS request` | `CORS_ALLOWED_ORIGINS` 与实际访问地址不一致（后端 prod 默认只放行 8080） | 在 `.env` 配成浏览器实际地址，**重建 backend**（environment 不热更新） |
| 用 `curl` 测一切正常，浏览器仍 403 | `curl` 默认不带 `Origin`，测不出跨域 | 复现时显式加 `-H 'Origin: http://<host>:<port>'` |
| 登录成功却进到 403 页 | 账号角色缺 `workbench:read`（读者账号登了管理端） | 换管理员 / 馆员账号；与 CORS 是两件事 |
| Flyway 报 checksum mismatch | 改了已执行过的迁移文件 | 迁移只前进：新增版本号，不改历史文件 |
| 时间差 8 小时 | 容器 `TZ` 与 JDBC `connectionTimeZone` 没一起设 | 两处都设 `Asia/Shanghai` |
| QQ 邮箱发不出 | 用了登录密码而不是授权码 / 发件人与认证账号不一致 | 用授权码；`MAIL_FROM` 必须等于认证账号 |

## 5. 技术入口（最小集）

```bash
# 全栈（Docker）
cp deploy/.env.example deploy/.env   # 必改：APP_JWT_SECRET / DB_* / RABBITMQ_* / CORS_ALLOWED_ORIGINS
docker compose --env-file deploy/.env -f deploy/docker-compose.yml up -d --build
curl -s http://localhost:8080/api/v1/system/health   # 期望 status=UP、baseTables=35
```

- 本地开发：JDK 21 + Maven / Node 20 + pnpm / MySQL 8 + Redis 7 + RabbitMQ 3；前端 `pnpm dev`（5173 已在默认白名单内）。
- 测试：后端 `mvn test`（142 例，141 过 / 1 跳过）、前端 `pnpm test`、客户端 `flutter test`（81 例）。
- 表结构：Flyway V1–V18，共 35 张表；演示数据由 `app.demo.enabled` 控制，**生产必须关闭**。
